# Latest reproducible method: balanced u5, fully raw feedback

[Live hourly results](live-run.md) · [Frozen source](../production/u5/SOURCE.json)

This is the current **128-state** source used by seed **9370001**, beginning
with empty event history at candidate 2. It is distinct from the earlier
8-state GPU runs and from the u4 matched/fresh ensembles. Its numerical source
has beta=1, pair strength u=5, balanced triple strength
 t=2.8465622403941495, Gamma=512, three readings and the uniform profile.

## Reproduce a prefix

Linux x86-64, Python 3.10–3.12, NumPy 1.26.4 and g++ are required. Allow at least
20 GiB free disk: the production runner deliberately stops below that reserve.

```bash
git clone https://github.com/iwtbotiwtwot/prime-event.git
cd prime-event
python3 -m venv .venv
. .venv/bin/activate
python -m pip install .
python scripts/reproduce_u5.py --workdir runs/u5-reference --chunks 20
python scripts/check_u5_replay.py runs/u5-reference
```

This executes **100,000,000 decisions**, through candidate 100,000,001, with
qualification seed 9369001. Each chunk has 5,000,000 decisions. The check compares
bank masks, emitted-event hashes, complete state, both RNG states and errors
against the frozen source qualification, rather than only checking zero errors.
The binary libraries compile locally from the included C++ sources; there is
no dependency on the private SAM checkout, GPU, SLC installation or a pod.

To reproduce the production seed from its beginning:

```bash
python scripts/reproduce_u5.py --workdir runs/u5-production --seed 9370001 \
  --workers 4 --cache-mib 4096 --chunks 20
```

Use the same absolute work directory, seed, mode and cache size when continuing.
Increase `--chunks` to the desired **total** chunk count; it is not an increment.
For example, a second invocation with `--chunks 40` continues to 200 million.
The wrapper's default per-invocation budget is one hour (`--seconds 3600`).
Create `runs/u5-production/data/STOP` for a clean checkpoint-boundary stop.
Remove that file only when you intend to resume. Checkpoints contain absolute
journal paths: keep the root fixed; moving an active dataset is not supported.

The frozen `.npy.gz` files are SHA-256 verified before materialization. They pin
the exact historical float64 CDF bytes, which can otherwise depend on numerical
library rounding. `runner.py`, random buffer code and both C++ sources are
byte-identical to the production source. Published compact evidence includes
the 100M reference, local pilot results and its independent verification.
The moving full raw production journal remains on T500; it is not bundled here.

## Source and feedback equations

There are seven dynamic spins: output e and six hidden spins; r1,r2 are the
two externally supplied bank signs. With p ranging over four sign triples
whose product is +1, the microscopic energy is

    E = -u h1(e+r1) - u h2(e+r2)
        -t sum_p z_p(1+p1 e+p2 r1+p3 r2).

The retained state encoding and signed patterns are in the existing
[recipe](../prime_event/sources/RECIPE.json). The source is generated by
single-spin heat-bath rates Q[z,n]=1/(1+exp(E[z]-E[n])), with the diagonal
minus the outgoing column sum. The pair and triple effective margins are

    a = log(cosh(2u))/2,
    b = (4 log(cosh(2t)) - log(cosh(4t)))/2.

Select t so a=b, now at u=5. Each reading uses exp((512/3)Q).
Initial state is sampled from the no-bank Gibbs distribution. Every candidate
advances the persistent state through three readings; emission requires the
accepted output bit on **all three**. The state is not reset between candidates.

An emitted event at n becomes an actual feedback period. Its proper multiples
activate its assigned bank; bank assignment alternates by the rank of the
**actual emitted events**, including any mistakes. Masks combine by Boolean OR,
not parity. The indexed history derives quotient ranges q*n in each candidate
window and fetches only intersecting authenticated event chunks. It preserves
rank and does not replace the history with a prime oracle.

Two PCG64 streams use seeds s and s+1,000,000. Four worker threads generate
exact disjoint subsequences of those streams; this is **one seed trajectory**,
not four trajectories. The first two readings use the extra stream and the
third uses the base stream, preserving the reference schedule.

**No repair, correction, learner or factor veto is active.** An independent
segmented sieve scores false emissions and missed primes after the gate has
acted. Its result never inserts or removes events, changes bank assignment,
or updates source state. Every gate emission feeds back unchanged.

## Implementation, performance and preservation

An isolated [GPU/CPU throughput pilot](throughput-pilot.md) adds exact speculative
transitions, parallel preparation and bounded RAM buffers. Its measurements and
validation are separate from the active production implementation described here.

Production runs on AMD Ryzen 9 8945HS, CPU affinity 1–7, four RNG workers,
NumPy 1.26.4 and g++ `-O3 -std=c++17 -shared -fPIC`. There is no GPU execution.
A bounded 4 GiB decoded-history LRU grows on demand. RAM buffers collect each
5M window. Compressed event gaps and state/RNG/error metadata are fsynced first;
the checkpoint is then atomically committed. There is no per-event disk write.
A writer lock rejects duplicate writers. Uncommitted future chunks are
quarantined on recovery. Progress is refreshed every 50M decisions.

The matched 100M pilot selected four workers: median complete loop throughput
12.03 million decisions/s, versus 11.31M/s with one and 11.88M/s with seven.
Six repeated trials and one restart execute 700M positions but cover only one
100M unique trajectory. They are implementation checks, not independent
accuracy exposure. The integration separately checked a 200M prefix and
85M→200M recovery, retaining identical emitted histories.

Current production continues without an overall deadline through automatically
renewed, resource-managed daily sessions. A clean time-budget stop resumes the
**same checkpoint and seed**. STOP, low storage, or a failure does not renew.
The 20 GiB disk reserve remains active; finite storage is not an indefinite
retention guarantee. No automatic pruning of scientific data is enabled.

The public hourly report records observed UTC/Chicago time, committed decisions
and both error types. Missing reports during workstation/network outages are
not fabricated. The run can continue on lilhelper while public reporting is
offline. See [automation](automation.md) for controls and exact scheduling.

record identify the earlier archived 0.1.1 release; this update does not claim
a new Zenodo deposit.
